# 설문 집계기 계획서

## 목표
엑셀에서 머리글 줄까지 복사해 붙여넣으면 문항별 결과 표(문항 / 유효 응답 / 평균 / 빈 응답 / 제외)를 보여 주는
`index.html` 한 파일짜리 도구.

## 지켜야 할 조건
- 외부 라이브러리·외부 글꼴·분석 도구 없음. 모든 CSS·JS는 `index.html` 안에 둔다.
- 붙여넣은 데이터는 브라우저 밖으로 보내지 않고 저장하지 않는다.
  - `localStorage`·`sessionStorage`·IndexedDB·쿠키·`fetch`·폼 전송을 쓰지 않는다.
  - CSP 메타 태그(`default-src 'none'`, `connect-src 'none'`, `form-action 'none'` 등)로 브라우저가 외부 연결을 막게 한다.
  - 입력칸은 `autocomplete="off"`, `spellcheck="false"`(브라우저 클라우드 맞춤법 검사로 내용이 나가는 것 방지).
- 저장소 맨 위에 빈 `.nojekyll` 파일(GitHub Pages가 Jekyll 처리를 건너뛰게).

## 집계 규칙
| 항목 | 규칙 |
|---|---|
| 줄 나누기 | 탭으로 칸, 줄바꿈(`\r\n`/`\n`/`\r`)으로 줄. 엑셀이 따옴표로 감싼 칸(칸 안 줄바꿈·탭)은 한 칸으로 읽는다. |
| 머리글 | 첫 줄. 첫 열(응답번호)은 집계하지 않고 둘째 열부터가 문항. 머리글 이름은 앞뒤 공백을 지운다. |
| 유효 | 앞뒤 공백을 지운 값이 `1` `2` `3` `4` `5` 중 하나 |
| 빈 응답 | 비었거나 공백만 있는 칸 |
| 제외 | 그 밖의 모든 값 (`0`, `6`, `1.0`, `３`, `예` 등) |
| 모자란 칸 | 칸 수가 머리글보다 모자란 줄은 모자란 칸을 빈 응답으로 센다 |
| 평균 | 유효 응답의 합 ÷ 유효 응답 수, 소수 셋째 자리에서 반올림해 둘째 자리까지(`3.50`처럼 항상 두 자리). 유효가 0이면 `-` |

### 계획서에서 정한 세부 결정 (요구에 명시되지 않은 부분)
- **완전히 빈 줄**(글자가 하나도 없는 줄)은 응답 줄로 보지 않고 건너뛴다. 엑셀 복사본 끝에 붙는 줄바꿈 때문에
  생기는 빈 줄이 응답으로 잡히지 않게 하기 위함. 탭만 있는 줄(엑셀의 빈 행)은 응답 줄로 세며 모든 칸이 빈 응답이 된다.
- **머리글보다 칸이 많은 줄**의 남는 칸은 대응하는 문항이 없으므로 집계하지 않고, 화면에 그런 줄 수를 알려 준다.
- **반올림**은 부동소수 오차를 피하려고 정수 연산으로 한다: `round(sum/n, 2) = floor((200·sum + n) / (2n)) / 100` (값이 양수라 절반 올림).
- 머리글 칸이 비어 있으면 문항 이름을 `(이름 없음 N열)`로 표시한다.
- 머리글만 있고 응답 줄이 없으면 표는 보여 주되 모두 0 / `-`.
- 머리글에 문항 열이 없으면(칸이 1개 이하) 오류 문구를 보여 준다.
- 화면에 넣는 글자는 모두 `textContent`로 넣어 붙여넣은 내용이 HTML로 해석되지 않게 한다.

## 구조
- `index.html` 안에 두 개의 `<script>`:
  - `<script id="tally-core">` — 화면(DOM)을 전혀 건드리지 않는 순수 계산 함수(`parseTable`, `classifyCell`, `formatAverage`, `tally`).
    브라우저에서는 `window.SurveyTally`로, Node에서는 `module.exports`로 내보낸다.
  - 화면 스크립트 — 입력을 읽어 `SurveyTally.tally`를 부르고 표를 그린다.
- `tests/` — Node 내장 시험 도구(`node --test`)만 쓴다(설치할 의존성 없음).
  시험은 `index.html`에서 `tally-core` 스크립트를 뽑아 `vm`으로 실행하므로, 배포되는 바로 그 코드를 시험한다.
  - `core.test.js` — 집계 규칙 시험
  - `page.test.js` — 외부 자원·저장소·네트워크 API를 쓰지 않는지, CSP가 있는지, `.nojekyll`이 빈 파일인지 검사
- `.github/workflows/test.yml` — 푸시·PR 때 `npm test` 실행.

## 작업 순서 (작업마다 커밋)
1. 계획서
2. `.nojekyll`
3. 계산 로직(`tally-core`)과 시험 도구·집계 시험
4. 화면(입력칸·결과 표)
5. 페이지 검사 시험과 CI
6. README 정리 → 시험 통과 확인 → PR
